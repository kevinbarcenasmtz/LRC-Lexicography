Files here are generated by `src/dravidian/scripts/build_dravidilex_import.py`.
Re-run the script after fixing anything upstream; do not hand-edit generated
outputs.

Current build-shaping guarantees:

- `HeadwordEntries` exists on all 28,612 reflex rows so Laravel does not
  comma-split raw `Headwords`.
- `EtymonEntry` exists on all 2,211 root rows, already asterisk-free for LRC
  etymon display.
- `Additional Forms` is normalized to `Additional forms`; regenerated JSON

- Root/etyma rows carry Starling provenance as `Source (StarlingDB)` extra data.
  Roots do not carry `Sources` because the platform has no `lex_etyma_source`
  table.

## Mapping Decisions

- **Starling dialects -> tree languages.** Starling splits dialect/source
  varieties that the import language tree does not. Each is mapped to its tree
  language for LRC (`Gondi` dialects -> `Gondi`; Kuwi source names -> `Kuvi`;
  `Ollari Gadba` -> `Ollari`; other Gadba varieties -> `Gadaba`; etc.). The
  original Starling language name is preserved as `Language (Starling)`.
- **Kasaba stays distinct** (Todd, 2026-07-05: err toward granularity on the
  first pass). It has its own language row under South / Proto-South Dravidian I.
- **`Proto-North-Dravidian`** is normalized to `Proto-North Dravidian`.
- **Empty North Dravidian placeholders are dropped.** The scrape emitted 563
  empty `Proto-North Dravidian` placeholder rows with no DED number, URL,
  reflexes, or distinguishing data. The build drops them before language-name
  normalization, preserving the real hyphenated rows and avoiding duplicate
  headword IDs.
- **Intermediate proto-languages** are explicit language rows:
  `Proto-South Dravidian`, `Proto-Central Dravidian`,
  `Proto-North Dravidian`, `Proto-Nilgiri`, `Proto-Telugu`,
  `Proto-Gondi-Kui`, `Proto-Gondi`, `Proto-Kui-Kuwi`,
  `Proto-Pengo-Manda`, and `Proto-Kolami-Gadba`. The top-level
  `Proto-Dravidian` is not a normal language row; all `Proto-Dravidian`
  records are root etyma, and the sidebar already gets its
  `/language/protolanguage` link from `lexicon.protolang_name`.

## Current Import Runbook

The current intended path is the isolated Laravel command on the
`feature/dravidilex-import-command` branch of `linguistics_research_center`.
The command creates the lexicon, languages, Buck semantic categories/fields,
2,211 etyma with semantic-field links, 28,612 reflexes, reflex-to-etymon links,
and reflex `Sources`.

The command **does not create landing pages or language pages**. Those stay out
of this import-command PR.

```bash
# JSON must be readable inside the container; for local Docker, copy it under server/ first.
cp /path/to/dravidilex_batch_import.json linguistics_research_center/server/storage/app/
docker compose exec web php artisan app:import-dravidilex-csv storage/app/dravidilex_batch_import.json
docker compose exec web php artisan app:generate-lexicon-data-cache <printed lexicon id>
```

For lrc-test/prod, Chris needs to run the same command server-side after the PR
is merged, then regenerate the lexicon data cache.

## Sources

`Sources` is emitted only for reflex rows and consumed by the Laravel import
command into the `lex_reflex_source` pivot:

- `DEDR`: full cleaned Burrow entry HTML by the reflex's own `Number in DED`.
- `STARLING`: compact rich citation with Starling database/text number/link.
- `CVOTGD`: page/entry-number-only for now; CVOTGD has not been scraped yet.

Source HTML is allowlist-sanitized in `build_dravidilex_import.py` before it
enters the JSON (`a`, `b`, `br`, `i`, `small`, `sup`). Laravel still needs the
blade view to render `original_text` as HTML for those citations to display as
intended.

## Semantic Tags

Semantic categories are no longer just flat extra data in the current import
path. The Laravel command seeds Buck categories/fields and creates
`LexEtymaSemanticField` rows for the 2,211 root etyma from
`Semantic Tag (Buck)`. This is what populates the Categories tab and the
Advanced Search `semantic_tag` column for reflexes linked to etyma.

Historical flat/browser-upload paths can still display the Buck tag as root
extra data, but they do not create real etyma or semantic-field links.
