# Context Of This Directory

This directory contains the cached Burrow DED corpus files used by the
Starling tree validator in:

`src/dravidian/scripts/cross-validating-dded-starling/starling_tree_validator.py`

The validator cross-checks Starling proto-tree language entries against Burrow
DED paragraph attestations.

---

## Core Task (Validation Goal)

For each Starling record with a DED number:

1. Look up the corresponding Burrow DED paragraph.
2. Verify each language entry under that Starling branch appears in Burrow.
3. Validate with tree context (proto hierarchy), not flat row matching.
4. Roll up branch status:
   - `fully_attested`
   - `partially_attested`
   - `not_attested`

Proto-Dravidian (root) is context only; validation applies to DED-bearing
branches below it.

---

## Source of Truth

**`burrow_corpus.json` is the single source of truth** for raw data.

It holds the HTML fetched from DSAL at scrape time (`raw_html`) and must
never be modified by downstream scripts. All derived files (`burrow_corpus.cleaned.json`)
are fully reproducible from it using `reparse_burrow_corpus.py`.

Do not re-run `burrow_corpus_scraper.py` unless new pages need to be fetched
from the network — the cached HTML is sufficient for all re-parsing and repair
work.

---

## Files In This Folder

### `burrow_corpus.json`

Original cached Burrow corpus from the scraper. **Do not modify.**

Contains:
- Entry metadata (`ded_number`, `edition`, `raw_html`, `full_text`)
- Parsed `attestations` with `language_abbrev`, `headwords`, `gloss`

Note:
- Attestations were parsed by whichever version of `BurrowEntryParser` was
  active at scrape time. Run `reparse_burrow_corpus.py` to update them when
  the parser changes.
- Gloss text may contain spacing artifacts from HTML parsing.

### `burrow_corpus.cleaned.json`

Repaired and re-parsed corpus derived from `burrow_corpus.json`. **Use this
file for all validator runs.**

Generated by `reparse_burrow_corpus.py`, which:
1. Re-runs the current `BurrowEntryParser` against every entry's `raw_html`
2. Replaces `attestations[]` with the freshly parsed result
3. Applies the gloss-repair and `id.` (idem) resolution pass from
   `repair_burrow_corpus_glosses.py`

The file embeds a `_reparse_meta` block recording the timestamp, script name,
and per-entry diff so you can audit exactly what changed in each rebuild.

### `review_ledger.json`

The triage decision log — **174 DED entries, 147 language-level records, 145 of them
`genuine_divergence`**. Hand-curated and irreplaceable: no script regenerates it, and it is
force-tracked in git (see `docs/SYNC.md` Tier 1).

⚠ **135 of the 147 language-level records carry `reviewed_by: claude-triage`** — they were
classified by an AI triage pass on 2026-08-20 and have had no human spot-check. Treat the
`genuine_divergence` set as asserted, not evidenced, until sampled.

> `burrow_corpus_checkpoint.json` was previously documented here. **It does not exist in this
> directory** — the scraper's resume state was not kept alongside the corpus.

## How To Run Validation

From repository root:

> **Path correction.** Earlier revisions of this file pointed at
> `data/dravidian/starling_complete_data.json`; the scrape lives one level deeper, in
> `data/dravidian/starling/`. The older name `starling_complete_data_scrape.json` refers to a
> **superseded scrape** that is no longer on disk — it was replaced by
> `starling_complete_data.json` and the markup superset `starling_complete_data_markup.json`.

```bash
# macOS
PYTHONIOENCODING=utf-8 ./lrc_venv/bin/python \
  src/dravidian/scripts/cross-validating-dded-starling/starling_tree_validator.py \
  data/dravidian/starling/starling_complete_data.json \
  --corpus data/dravidian/burrow_ded/burrow_corpus.cleaned.json \
  --output-dir data/dravidian/cross-validating-dded-starling/tree_validation_output
```

Test mode (first N records): append `--test 2`.

**Expected result (pilot-frozen, 2026-08-21):** `entries_matched` **19,083 / 19,354**,
`entry_match_rate` **98.6%**, `Language only` 136, `No` 135, plus **653** subgroup-DB orphans
excluded from the denominator. Compare against `data/dravidian/cross-validating-dded-starling/tree_validation_output/tree_validation_summary.json`
(tracked in git). Read `docs/dravidian_validator_progress.md` §11 before quoting the rate anywhere.

## Validation Outputs

By default, outputs go to `data/dravidian/cross-validating-dded-starling/tree_validation_output/`:

- `tree_validation_results.xlsx`
  — Primary row-level validation output.
- `tree_validation_results.csv`
  — CSV mirror of row-level validation output.
- `coverage_by_ded_paragraph.xlsx`
  — Per-DED coverage rollup (row and language overlap metrics).
- `validation_audit_report.xlsx`
  — Reviewer-oriented issue report with sheets:
    - `row_issues`
    - `meaning_mismatches`
    - `missing_starling_meaning`
    - `branch_rollup`
    - `ded_rollup`
- `tree_validation_summary.json`
  — High-level numeric summary.
